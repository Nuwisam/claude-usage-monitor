# AX206 panel — client dependencies.
#
# Hard pins: what draws on the display must not change because someone ran
# `pip install -U` for a different project. The venv lives OUTSIDE the repo,
# in %LOCALAPPDATA%\claude-usage-monitor\panel-venv (see deploy/install-task.ps1).
#
# The rest of the client is stdlib: http.client, ssl, ctypes, winreg, queue, threading.
# numpy is NOT needed — RGB565 packing goes through bytes.translate()
# and a single OR operation on large integers, 1.55 ms for a full frame.

Pillow==12.1.0
# libusb carries the libusb-1.0.dll binary for win-amd64 — the library alone, without
# a driver. The device's DRIVER remains libusb-win32 (`libusb0.sys`,
# the same one the ready-made tools for these displays use); the libusb-1.0 Windows backend talks to it
# without re-binding anything (measured: 1200 frames, missed_csw=0).
#
# Why libusb-win32 was not kept: its 0.1 API does not report topology
# (bus-0, devnum=0), so the module had to be looked up in the Windows registry and matched
# one to the other by ordering. `libusb_get_port_numbers()` gives the port chain
# straight from the handle being opened. Details in the panel/device.py header.
libusb==1.0.29.post7
# certifi is a CA store — refreshing it is to be a decision, not a side effect.
# Bump it deliberately, once it stops trusting your server's certificate chain.
certifi==2026.7.22
# pyserial drives the SECOND screen (Turing rev A on a CH340). The version is pinned
# also because the driver reads one private thing from it: the byte meter
# from `_overlapped_write.InternalHigh` after a write that timed out. Without it there
# is no way to push through the exact remainder of a truncated bitmap, and that is the
# only known way out of a desync on a link that acknowledges nothing.
pyserial==3.5
